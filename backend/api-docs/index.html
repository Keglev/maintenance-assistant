Query

Question answering over the indexed maintenance protocols

Ask a question about one machine

Embeds the question, retrieves the closest protocol chunks for that machine and answers in one of two modes. Mode A is grounded: every claim carries the source it came from, validated against what was actually retrieved. Mode B is a labelled general suggestion, returned when no stored protocol is close enough. The answer is written in the language of the question, and its depth depends on the caller's role.

Moderation

Administrator review and removal of protocols

List every protocol in the corpus, newest first

Paged. size is clamped to 50 — the corpus grows every time a protocol is uploaded, and an unpaged list of it is a page that gets slower forever. Optionally narrowed by machine, by a case-insensitive title substring and by an upload-date range. titleContains, from and to require machineNo: without it they answer with rows from machines the reviewer was not looking at. All four absent is the plain list.

Remove a protocol from the corpus, permanently

Deletes its chunks, its row and its file. There is no undo and no soft delete: correcting a protocol is delete-then-reupload, so that no answer can cite text that changed underneath it (ADR-006).

Queue unindexed protocols for indexing

Finds protocols in the given statuses and hands them to the indexer. Idempotent: re-indexing replaces a protocol's chunks rather than adding to them. Defaults to RECEIVED; pass FAILED to retry failures.

What happened to the protocols you uploaded

The 50 most recent uploads of the calling user, newest first, with status RECEIVED / INDEXED / FAILED and the failure reason. Upload answers 202, so this is where a document becoming searchable is actually visible.

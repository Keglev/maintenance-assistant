     C6  application.yml — THE http SERVER URL, RE-MEASURED AND ITS CAUSE
         FOUND. Carried out of Part 1 as "springdoc deriving the server
         behind the proxy". Still true 2026-08-25:
           curl -s https://maintenance.smartsupply.com.de/v3/api-docs
           servers: [{"url":"http://maintenance.smartsupply.com.de",
                      "description":"Generated server url"}]
         OpenApiConfig sets .info and .components and NO .servers, so
         springdoc derives it from the request. Caddy
         terminates TLS and proxies plain HTTP to backend:8080, so the
         request the application sees IS http — and nothing tells it
         otherwise: `grep -rn "forward-headers" backend/src docker/`
         returns nothing. The absent setting is
         server.forward-headers-strategy, which would make Boot honour
         the X-Forwarded-Proto Caddy already sends. Not a deployment
         fault and not a springdoc bug: a missing property. FIX, and it
         is one line — but it changes what a published document says, so
         it is a ruling before it is an edit.
         FIXED 2026-08-25, #99: property server.forward-headers-strategy:
         framework added to application.yml, test ForwardedHeadersIT.
         DEPLOY REQUIRED — backend image; verify the live servers URL after
         deploy. THIS IS THE FIRST PART 3 CHANGE THAT ALTERS PRODUCTION
         BEHAVIOUR; every earlier PR in the wave was comments, ledgers or
         dev-only files, and CI green does not finish this one.
         THE STOP CONDITION WAS CHECKED BY MEASUREMENT, NOT BY READING.
         Before the property was added, the new test ran and failed with
           expected: "https://maintenance.smartsupply.com.de"
            but was: "http://localhost:54027"
         which proves springdoc DERIVES servers from the request in this
         version — so the fix is the property and a hardcoded servers entry
         would have been the wrong shape. With the property: 2 of 2 pass.
         framework over native: native delegates to the container valve,
         which only Tomcat has and which needs its own trusted-proxy list;
         framework is Spring's ForwardedHeaderFilter, container-independent,
         and honours X-Forwarded-Prefix as well.
         THE SPEC WAS ONLY THE VISIBLE SYMPTOM. Redirect Location headers
         and every other absolute URL the application derives from a request
         carried the same defect; one property fixes the class.

          CHECKING OUT gh-pages into a staging directory. That is the
          step that does not exist today, and it is the whole idea: the
          published site becomes an input to the publish rather than a
          thing the publish half-overwrites.
       3. It replaces, wholesale, only the subtrees this run rebuilt —
          rm -rf the destination, then copy — and leaves the others as
          checked out. A rename now deletes, because the site tree is
          replaced rather than merged into.
       4. keep_files: false, publishing the staged tree. The four trees
          survive because they are IN the staged tree, not because the
          publisher was told not to delete.

     WHAT THIS MUST NOT BREAK, and each is a real hazard:
       - The .nojekyll file at the root is not produced by any build.
         Under keep_files it survives by luck. A staged publish must
         write it deliberately or the site stops serving underscore
         paths.
       - The concurrency group must stay `gh-pages` with
         cancel-in-progress: false, and it becomes MORE load-bearing,
         not less: a checkout-modify-publish cycle has a window a plain
         overwrite does not.
       - The first run under this scheme deletes six files (C2). That
         is the point, and it should be a deliberate first run with the
         diff read, not a side effect of merging the change.
       - Whether LICENSE and README.md at the site root should exist at
         all is a content question this sketch does not answer — it only
         makes the answer enforceable.
     NO PREDICTED OUTCOME NUMBERS: this is a shape, and the PR that
     builds it measures what it actually publishes.

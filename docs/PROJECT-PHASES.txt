GIT WORKFLOW (MANDATORY FOR EVERY AI SESSION — no exceptions)
=====================================================================
- Work on exactly ONE branch, created from up-to-date main:
    git checkout main && git pull && git checkout -b <type>/<short-name>
  Never create additional branches. Never commit or push to main
  (branch protection rejects it anyway).
- Commit in small logical units as you work, not one commit at the end.
- Conventional Commits: type(scope): imperative summary, max 72 chars.
  Types: feat, fix, chore, docs, ci, test, refactor.
  Scopes: backend, frontend, docker, docs, ci.
  Body (wrapped ~72 chars) explaining WHY when not self-evident.
  Never mention AI, Claude, or "generated" in commit messages.
- Before finishing: run `git log --oneline main..HEAD`, show the list,
  reword anything vague (no "update files", no "changes").
- Push the branch and open the pull request yourself:
    gh pr create --base main --title "<conventional title>" \
      --body "<markdown: What / Why / Verification / Out of scope>"
- Print the PR URL as final output. NEVER merge — merging is done
  manually by Carlos after review.

PIPELINE ARCHITECTURE (.github/workflows/)
1. frontend-ci.yml    PR + push main (paths frontend/**): test with
                      coverage (test runner: vitest in jsdom — no
                      browser needed on the runner), build; upload
                      coverage + Compodoc artifacts on main
2. backend-ci.yml     PR + push main (paths backend/**): mvn verify
                      (JUnit + JaCoCo), OpenAPI spec; upload artifacts
                      on main
3. frontend-deploy.yml / backend-deploy.yml
                      push main, after CI success: multi-arch docker
                      build (amd64+arm64) -> GHCR. Hetzner deploy =
                      commented TODO until VPS exists.
4. docs.yml           a) push main paths docs/**: regenerate mermaid
                         diagrams, build Jekyll site -> gh-pages
                      b) workflow_run success of frontend-ci/backend-ci:
                         publish coverage + API docs into gh-pages
                         subfolders (/frontend/coverage, /frontend/
                         api-docs, /backend/coverage, /backend/api-docs)
                         WITHOUT deleting the rest (keep_files)
5. release.yml        tag v*: GitHub Release with generated notes
